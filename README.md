# 🎭 舞台换景顺序优化器

在满足**前后依赖**、**固定序位**、**禁止相邻**三类约束的前提下，自动求出
**换景道具增减次数最少**的场景演出顺序，并逐次列出每次换景需要**增加/移除**的道具。
无解时给出一组**可复现的极小冲突约束**。支持方案保存与重新编辑。

- 后端：Node.js + Express（无构建步骤、原生前端）
- 前端：原生 HTML / CSS / JavaScript
- 算法：子集动态规划（n ≤ 12，O(n²·2ⁿ)）
- 存储：JSON 文件持久化（容器卷），无需数据库

docker build -t stage-scene-optimizer . && docker run -d -p 3000:3000 -v stage-data:/app/data --name stage-optimizer stage-scene-optimizer

## 📖 使用说明

1. **录入场景**：最多 12 个，为每个场景填写名称与道具
   （逗号 `,`、顿号 `、`、分号、空格、换行均可分隔，自动去重）。
2. **设置约束**（均可留空）：
   - **前后依赖**：A 必须在 B 之前演出；
   - **固定序位**：把某场景钉死在第几位（序位从 1 开始）；
   - **禁止相邻**：两个场景在演出顺序中不能紧挨着。
3. 点击 **「计算最优顺序」**。
4. 结果区展示：
   - 最优顺序与**换景道具增减总次数**（优化目标）；
   - **装台**（空台 → 第 1 场）与**卸台**（末场 → 空台）道具，单独统计供参考；
   - **每次换景明细**：从哪场到哪场、增加哪些道具、移除哪些道具、本步增减几件。
5. **保存方案**：输入名称后保存；在页面下方“已保存方案”中可随时
   **载入并编辑**（载入后恢复全部输入，可修改后重新计算、覆盖保存）或删除。
6. 点击 **「载入示例」** 可快速体验完整功能。

### 优化目标口径

每件道具的一次“增加上场”或“移除撤场”计 1 次；
优化目标为**相邻场景之间**的增减总次数（即 Σ |道具集合对称差|），
不包含一次性的装台与卸台（二者在结果中单独展示，避免把“先演哪场”的选择与装台混为一谈）。
存在多个等优顺序时，按场景录入顺序返回字典序最先者，结果**确定可复现**。

### 无解时的冲突报告

当约束互相矛盾（如依赖成环、固定位与依赖冲突、禁止相邻把排列空间封死等）时，
系统返回 HTTP 422 并给出一组冲突约束：

- 优先给出**结构化解释**（如「A→B→C→A 构成环路」「A 必须在 B 之前，但固定序位把 A 放在 B 之后」）；
- 无法结构化命名时，给出一个**极小不可满足约束核（MUS）**：删除其中**任意一条**约束后即恢复可解。
  该集合由确定性的逐条删减法算出，便于稳定复现与排查。

## 🔌 HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/solve` | 计算最优顺序。成功返回 200；有冲突无解返回 422（含 `conflicts`）；输入非法返回 400 |
| `GET` | `/api/plans` | 方案列表（摘要） |
| `POST` | `/api/plans` | 新建方案；body 中带已存在的 `id` 时为更新 |
| `GET` | `/api/plans/:id` | 获取单个方案（含完整输入与上次结果） |
| `DELETE` | `/api/plans/:id` | 删除方案 |

`POST /api/solve` 请求体示例：

```json
{
  "scenes": [
    { "id": "s1", "name": "王宫", "props": ["王座", "立柱"] },
    { "id": "s2", "name": "森林", "props": ["树木", "立柱"] }
  ],
  "dependencies": [["s1", "s2"]],
  "fixed": [{ "id": "s1", "pos": 1 }],
  "forbidden": []
}
```

无解响应示例：

```json
{
  "feasible": false,
  "method": "mus",
  "hint": "下面这组约束构成一组极小冲突：删除其中任意一条后，剩余约束即可满足。",
  "conflicts": [
    { "type": "mus-dep", "message": "「森林」必须在「王宫」之前演出", "refs": [1, 0] },
    { "type": "mus-fixed", "message": "「森林」固定在第 2 位", "refs": [1] }
  ]
}
```

## 算法说明

采用 Held–Karp 式子集动态规划：

- 状态 `dp[mask]`：已排布场景集合为 `mask` 时的最小增减次数；
- 转移时按三类约束剪枝：
  前驱必须全部已排（依赖）、当前序位与固定序位一致、与上一场不构成禁止相邻；
- 边界 `dp[0]=0`，答案为 `dp[(1<<n)-1]`，并记录父状态回溯出顺序。

n = 12 时状态数 4096、转移约 50 万次，浏览器同机毫秒级完成。
